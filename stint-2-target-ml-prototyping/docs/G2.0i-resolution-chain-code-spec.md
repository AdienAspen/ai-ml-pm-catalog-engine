# G2.0i resolution chain - code-derived specification

Scope: B1 relational orders only. This document describes the existing
instrument; it does not approve a new resolution rule. Source of truth
remains the frozen code and manifests.

## Inputs and links

1. G1.2 supplies the order-to-site/turbine join. An order without
   `matched_asset_node` has no turbine root. G2.0i checks the 10,749
   order keys against G1.2 before scoring
   (`g20i_component_resolution.py`, `read_g12`, lines 140-153; `run`,
   lines 307-318, 383-394).
2. G2.0c Step 5 detects concepts by exact contiguous phrase matching
   on the full masked, normalized `reason` and `descriptionExtended`
   segments. It does not embed whole order text or truncate at 128
   tokens (`g20c_step5_coverage.py`, lines 279-311). G2.0i retains
   only the 40 final assigned Object Part concepts and their unit hits;
   three formerly unassigned concepts are excluded
   (`g20i_component_resolution.py`, lines 156-191).
3. Candidate nodes are strict descendants of the order's matched
   turbine, never the turbine root or nodes from other turbines/sites.
   A candidate requires non-empty normalized IH06 description and a
   valid effective RBNR. Effective RBNR is the nearest valid profile
   walking up `Superior functional location`; an unprofiled node with
   no valid ancestor is excluded before scoring
   (`g20i_component_resolution.py`, lines 71-100, 119-136, 193-205,
   320-350). This is why a separate post-selection `node_no_profile`
   failure is impossible.
4. MiniLM (`paraphrase-multilingual-MiniLM-L12-v2`) embeds the 40
   normalized concept canonical labels and normalized IH06 candidate
   descriptions, not order text. Cosine scores use L2-normalized
   vectors. For each node the score is the maximum across **all**
   detected concepts. Nodes are ranked by that score; a node is
   resolved when best score is at least 0.60 and best minus second is
   at least 0.05. Below 0.60 is abstained; a smaller margin is a node
   tie (`g20i_component_resolution.py`, lines 207-212, 359-406).
5. G2.0i's additive profile-consensus pass leaves node states
   unchanged. For a node tie, take **every** candidate with
   `best_score - node_score < 0.05`. Emit a profile only if all those
   nodes share one valid RBNR; checking only the top two is insufficient
   (`g20i_profile_consensus.py`, lines 30-37, 151-187).

## What persists

- `g20i_order_resolution_sanitized.csv`: per-order node status,
  reason, number of detected concepts, top and runner node hashes,
  rounded best/runner scores, margin, and RBNR **only for resolved
  nodes**. It does not retain all candidate scores, the winning
  concept per node, or visible descriptions.
- `g20i_profile_consensus_by_order_sanitized.csv`: per-order profile
  status, RBNR when resolved, near-top node and distinct-profile
  counts for original node ties. It does not retain the tie set or
  per-node scores.
- `g20k_expansion_affected_orders_sanitized.csv`: 459 originally
  unresolved orders with one or more additional G1.1e-derived phrases,
  their expanded profile status, and supplemental concept IDs. G2.0k.2
  affects only the original unresolved set; the 3,934 already resolved
  profiles remain untouched.
- `g20k3_order_stage_sanitized.csv`: one partition category per B1
  order. `winning_concept_id` is populated for `concept_no_node` only,
  **not** for ambiguous-node orders. It does not retain all candidate
  scores. A structural tie diagnostic therefore needs a deterministic
  replay, with category identity asserted before analysis.

## Boundaries

The 0.60 score and 0.05 margin are diagnostic, not independently
calibrated FLOC accuracy. Profile restriction and any downstream
catalogue-code evaluation are dependent on the same Object Part text
signal. Neither node nor code correctness follows from a resolved
profile. No promotion or F6 denominator change is implied.
